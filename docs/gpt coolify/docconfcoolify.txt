Sim. Primeiro ponto importante:

No Supabase você não “cria várias bases” como no SQL Server.
Você já tem 1 PostgreSQL rodando.
Agora você cria tabelas/schemas dentro dele.

Para TST/PRD, o ideal é:

Supabase TST = 1 Resource separado
Supabase PRD = outro Resource/VPS/Cloud

Na sua VPS KVM2, eu manteria esse Supabase como TST/HOM, porque já tem Evolution + n8n.

Onde criar tabelas

No Supabase Studio:

Menu esquerdo → Table Editor → New Table

Exemplo:

Tabela: clientes
Schema: public
Colunas:
id uuid primary key
nome text
created_at timestamptz

Também pode criar via:

Menu esquerdo → SQL Editor
Seus secrets

Para este ambiente, ficaria assim:

SUPABASE_PRD_URL=https://supabase.hagap.online
SUPABASE_PRD_ANON_KEY=pegar no Coolify
SUPABASE_PRD_SERVICE_ROLE_KEY=pegar no Coolify
SUPABASE_PRD_PROJECT_REF=hagap-prd
SUPABASE_ACCESS_TOKEN=usar somente se for Supabase Cloud/CLI

As chaves anon e service_role são chaves de API do projeto; a service_role nunca deve ir para frontend/browser porque ignora RLS.

O SUPABASE_ACCESS_TOKEN é usado pela Supabase CLI/ambientes CI para comandos não interativos; ele é do Supabase Cloud, não do seu self-hosted local no Coolify.
